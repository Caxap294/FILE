## Часть 2. Шаблон описания для ветки
1. **Что сделано:** Перечисление того, что было добавлено в код.
2. **Зачем:** Название задания или цель работы.
3. **Как проверить:** Инструкция, как запустить код и что вводить для проверки.
4. **Ограничения:** Известные ошибки в коде, которые пока не исправлены.

## Часть 3. Лишние файлы
- `__pycache__/` — ненужная папка, которую компьютер создаёт сам при запуске программы.
- `.DS_Store` — технический файл системы, для работы кода он не нужен.
- `todo.txt` — личный файл с записями, который забыли удалить.
- `venv/` — папка со служебными настройками, её не нужно загружать в репозиторий.

## Часть 6. Этика обратной связи
### 5 правил
1. Говори только про ошибки в коде, не оценивай самого человека.
2. Точно указывай номер строки, где найдена проблема.
3. Объясняй, к какой ошибке приводит эта строчка кода.
4. Предлагай готовый вариант исправления.
5. Сначала похвали те части программы, которые работают хорошо.

### Переписанные замечания (2 шт.)
**Было:** «На 7 строке плохой код, всё ломается от букв, переделывай».
**Стало:** «Хорошо, что выбор случайного числа работает правильно. Но на 7 строке программа выключается, если ввести буквы. Нужно добавить проверку, чтобы код не ломался. Если нужно, я могу подсказать решение».

**Было:** «Зачем ты написал SECRET большими буквами? Исправь».
**Стало:** «Программа запускается отлично. Но на 3 строке имя переменной SECRET написано большими буквами. Так принято писать только постоянные значения. Лучше написать маленькими буквами».
